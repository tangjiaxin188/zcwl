# X11 后端设计

**状态**：设计阶段，尚未实现代码。  
目标是与现有 Wayland 后端保持相同的公开行为，并让 `example/draw_triangle.zig` 在
`-Dbackend=x11` 下直接运行。

## 0. 目标与约束

- 窗口、上下文、事件、剪贴板、监视器、光标、装饰、IME、Vulkan WSI 与 Wayland 后端对齐。
- 输入事件对齐：
  - 鼠标、触控板 → 鼠标事件；
  - 触摸屏 → 鼠标左键事件（不新增 touch 类型）；
  - 数位笔 → `pen_*`，包含压感、tilt、rotation、按键、橡皮擦；
  - 键盘 → `key_down/key_up/text_input`。
- 目标：X11 后端实现后，`example/draw_triangle.zig` 可通过
  `zig build run example -Dbackend=x11` 运行。当前 `-Dbackend=x11` 会在构建期被拒绝。
- **默认不链接 X11 库**：`libX11`、`libXi`、`libXrandr` 通过 `dlopen` 加载，
  构建时只依赖头文件/translate-c 生成物，不产生 `-lX11`。
- 尽可能复用：
  - `src/linux/egl.zig`；
  - `src/linux/xkb.zig` 的 `mapKey`；
  - `src/Event.zig`、`General.zig`、`Config.zig`、`Vulkan.zig`；
  - 后端 selector、事件队列和错误上报约定。

公共部分：

- `src/linux/egl.zig` 增加 X11 platform 常量，EGL 加载器本身不变；
- 把 Wayland 的通用事件队列抽到 `src/linux/event_queue.zig`（只负责
  `Event.Core` 的入队/出队，不依赖 Wayland 类型）；
- `src/linux/xkb.zig` 的 keysym → `Event.KeyCode` 映射直接复用；
- 不修改 `General/Event/Config/Vulkan` 的公开语义。

## 2. 构建、链接与绑定生成

### 2.1 不链接 X11

`loader.zig` 使用 `std.DynLib`，候选名和环境变量覆盖：

| 库 | 默认候选 | 覆盖变量 |
|---|---|---|
| Xlib | `libX11.so.6`, `libX11.so` | `ZCWL_X11_LIB` |
| XInput2 | `libXi.so.6`, `libXi.so` | `ZCWL_XI_LIB` |
| XRandR | `libXrandr.so.2`, `libXrandr.so` | `ZCWL_XRANDR_LIB` |

`libXi` / `libXrandr` 缺失时降级：

- 没有 XI2：鼠标/键盘仍可用 core Xlib，触摸和数位笔不可用；
- 没有 XRandR：`getMonitors` 返回一个基于 `DisplayWidth/DisplayHeight` 的兜底项。

构建只链接 libc（`dlopen` + `dlsym` 需要），不链接 X11 库。

### 2.2 类型和事件结构

Xlib 的 `XEvent` 是大型 union，手工声明容易和 ABI 不一致。设计采用与 Wayland
协议相同的方式：

```c
/* src/linux/x11/bindings.h */
#include <X11/Xlib.h>
#include <X11/Xutil.h>
#include <X11/Xatom.h>
#include <X11/cursorfont.h>
#include <X11/XKBlib.h>
#include <X11/extensions/XInput2.h>
#include <X11/extensions/Xrandr.h>
```

`build.zig` 在 `backend == .x11` 时：

1. `zig translate-c` 生成 `src/linux/x11/bindings.zig`；
2. 不编译任何 X11 C 源文件；
3. Zig 代码只使用绑定里的**类型**，所有函数通过 `loader.zig` 的函数指针调用。

注意：不能直接使用 `@TypeOf(c.XOpenDisplay)` 之类的外部函数符号，否则 Debug 构建
会产生未定义符号；`loader.zig` 必须像 Wayland 的 EGL 加载器一样手写函数指针类型。

## 3. 初始化流程

`Backend.init`：

1. `XOpenDisplay(null)`；失败返回 `error.X11ConnectFailed`；
2. 可选调用 `XInitThreads`（库本身仍声明非线程安全）；
3. 保存 screen、root、默认 visual/depth；
4. 初始化 atoms：`WM_DELETE_WINDOW`、`WM_CLASS`、`_NET_WM_NAME`、`_NET_WM_STATE`、
   `_NET_WM_ICON`、`_NET_WM_WINDOW_OPACITY`、`_NET_ACTIVE_WINDOW`、`CLIPBOARD` 等；
5. `XRRSelectInput(root, RRScreenChangeNotifyMask)`（有 XRandR 时）；
6. `XIQueryVersion(2, 2)`；失败则禁用 XI2 触摸/数位笔；
7. `XOpenIM`，失败时 IME 降级为 keysym 文本；
8. 建立内部 `Backend`、窗口表、事件队列；
9. 创建剪贴板 owner window（不可见，处理 SelectionRequest）；
10. 初始化 EGL display 延迟到第一次 `initContext`，或构造时缓存 EGLDisplay。

`initWindow` 的关键顺序：

```text
eglGetPlatformDisplayEXT(EGL_PLATFORM_X11_KHR, Display, null)
  -> eglInitialize
  -> eglChooseConfig（默认 alpha >= 8，32-bit visual 优先）
  -> eglGetConfigAttrib(EGL_NATIVE_VISUAL_ID)
  -> XMatchVisualInfo
  -> XCreateWindow
  -> XStoreName / _NET_WM_NAME / WM_CLASS
  -> WM_DELETE_WINDOW
  -> XMapWindow
  -> XSync
```

没有可用 32-bit ARGB visual 时回退 24-bit visual；透明由 compositor 决定。

## 4. 事件泵与事件队列

- `pollEvent` 使用 `XPending(display)`；只有 `XPending > 0` 时才 `XNextEvent`，
  不会阻塞。
- `XNextEvent` 取到的事件先经过 `event.zig` 分发，可能向内部队列 push 多个
  `Event.Core`，最后弹出一个。
- 不使用 `XPeekEvent` 做阻塞等待；应用想等待时可自己 `poll` X11 fd 后调用
  `pollEvent`。
- `XFlush` 在每次请求批处理后调用。
- `window_should_close` 仅由 `WM_DELETE_WINDOW` ClientMessage 产生；不主动销毁窗口。
- 过期事件只带 `window_id`，由应用通过 `App.getWindowById()` 判定。

需要处理的核心事件：

| XEvent | 映射 |
|---|---|
| `ConfigureNotify` | 更新 size/position，push `window_resized`/`window_moved` |
| `ClientMessage(WM_DELETE_WINDOW)` | `window_should_close` |
| `ClientMessage(_NET_WM_STATE)` | 更新最大化/全屏/置顶状态 |
| `FocusIn/FocusOut` | `window_focus_gained/lost` |
| `MapNotify/UnmapNotify` | 更新 minimized/restored |
| `PropertyNotify` | 剪贴板、`_NET_WM_STATE` 等异步结果 |
| `SelectionRequest/SelectionNotify` | 剪贴板 |
| `ClientMessage(XdndEnter/Position/Leave/Drop)` | 文件拖拽事件；见 8.5 |
| `RRScreenChangeNotify` | 重建 monitor 列表 |
| `XI_TouchBegin/Update/End` | 鼠标左键事件 |
| `XI_Motion/ButtonPress/ButtonRelease` | 鼠标或数位笔 |
| `KeyPress/KeyRelease` | 键盘 + XIM |
## 5. Window / EWMH 映射

X11 的窗口装饰、置顶、全屏等由 WM/EWMH 决定，后端通过属性与 ClientMessage 实现。

| API | X11 实现 |
|---|---|
| `setTitle/getTitle` | `_NET_WM_NAME`（UTF8_STRING），回退 `WM_NAME`；后端保存副本 |
| `app_id` | `WM_CLASS` 的 instance/class，取 `Config.AppConfig.application_id` |
| `setSize/getSize` | `XResizeWindow` / `XGetWindowAttributes` |
| `setPos/getPos` | `XMoveWindow`；`XTranslateCoordinates` 获取全局位置 |
| `getFramebufferSize` | `getSize() * getDpiScale()`；X11 像素坐标 |
| `setMinSize/setMaxSize` | `XSizeHints`（`PMinSize`/`PMaxSize`） |
| `setResizable` | `PMinSize == PMaxSize` 近似固定尺寸 |
| `setFullscreen` | `_NET_WM_STATE_FULLSCREEN` ClientMessage |
| `minimize` | `XIconifyWindow` |
| `maximize` | `_NET_WM_STATE_MAXIMIZED_HORZ/VERT` |
| `setFocus` | `_NET_ACTIVE_WINDOW` ClientMessage + `XRaiseWindow` |
| `requestAttention` | `_NET_WM_STATE_DEMANDS_ATTENTION` |
| `setDecorated` | `_MOTIF_WM_HINTS` 的 decorations 位；WM 不支持时记录请求 |
| `setAlwaysOnTop` | `_NET_WM_STATE_ABOVE`；比 Wayland 的标准支持好 |
| `setOpacity` | `_NET_WM_WINDOW_OPACITY`（32-bit cardinal）；无 compositor 时无效果 |
| `setIcon` | `_NET_WM_ICON`，ARGB 数组；X11 可真正实现 |
| `setAspectRatio` | `XSizeHints` 的 `PAspect` |
| `setCursor` | `XCreateFontCursor` + `XDefineCursor` |
| `setCursorVisible` | 空白 cursor 或恢复 |
| `setImeAllowed` | 启用/禁用 XIM IC |
| `setImeCursorArea` | XIM `XNSpotLocation`（按窗口逻辑坐标） |

`_NET_WM_STATE` 需要发送到 root 的 ClientMessage，`data.l[0]` 使用
`_NET_WM_STATE_ADD/REMOVE/TOGGLE`，`data.l[1..2]` 是目标 state atoms。

窗口状态通过 `PropertyNotify` 或 ClientMessage 回读，不要只相信请求已经生效；
`getInfo()` 返回后端缓存的实际状态（与 Wayland 一样）。

### 5.1 装饰

- X11 的装饰由 WM 提供，客户端没有真正 CSD 义务；
- `setDecorated(false)` 设置 `_MOTIF_WM_HINTS` 的 `decorations = 0`；
- 少数 WM 不识别 Motif hints，此时属性已写入，但视觉效果由 WM 决定；
- 不实现自绘 CSD，避免引入一整套窗口边框/命中测试。

### 5.2 透明

- EGL config 优先选择 `EGL_ALPHA_SIZE >= 8` 且匹配 32-bit visual；
- 设置窗口背景为 `None`，避免 X11 先用不透明背景清屏；
- 需要 compositor 才能看到逐像素 alpha；没有 compositor 时表现为不透明；
- `setOpacity` 是 EWMH 整窗透明度，与逐像素 alpha 是两条路径。

## 6. EGL Context / Vulkan

### 6.1 EGL

复用 `src/linux/egl.zig`，只需增加：

```zig
pub const PLATFORM_X11_KHR: Enum = 0x31D5;
```

`Context.init`：

```text
eglGetPlatformDisplayEXT(EGL_PLATFORM_X11_KHR, Display, null)
  -> eglInitialize
  -> eglBindAPI(GL/GLES)
  -> eglChooseConfig（alpha 8，32-bit visual 优先）
  -> eglCreateContext(..., share.context, ...)
  -> eglCreateWindowSurface(display, config, XID, null)
  -> eglMakeCurrent
```

`NativeContext` 与 Wayland 一致，仍是 EGLDisplay/EGLConfig/EGLContext/EGLSurface；
`General.NativeWindow.ndt` 是 `Display*`，`nwh` 是 X11 `Window`（XID）。
`Context.resize` 只需更新缓存的窗口尺寸；EGL X11 surface 随 X Window 尺寸变化，
不需要 wayland-egl 那种 resize 调用。

### 6.2 Vulkan

- `getVulkanInstanceExtensions()` 返回 `VK_KHR_surface`、`VK_KHR_xlib_surface`；
- `Window.createVulkanSurface` 调用调用方提供的 `vkCreateXlibSurfaceKHR`；
- `VkXlibSurfaceCreateInfoKHR`：`dpy = Display*`，`window = XID`；
- 不创建 instance/device/swapchain，透明仍由用户 swapchain 决定。

## 7. 输入设计

### 7.1 事件源选择

X11 有两套输入路径：

- core Xlib：`KeyPress`、`ButtonPress`、`MotionNotify`、`EnterNotify`；
- XInput2：鼠标/触控板/触摸/数位笔的详细设备事件和 valuator。

设计原则：

- 键盘始终使用 core/XKB + XIM；
- 鼠标、触控板、触摸、数位笔优先使用 XInput2；
- 如果 XI2 初始化失败，鼠标/触控板回退 core Xlib；
- 同一窗口不要同时处理 core 和 XI2 的同一类指针事件，避免重复。
  采用 XI2 时窗口的 core pointer mask 只保留窗口生命周期相关事件，或过滤重复事件。

XI2 选择：

```text
XI_ButtonPress | XI_ButtonRelease | XI_Motion |
XI_Enter | XI_Leave |
XI_TouchBegin | XI_TouchUpdate | XI_TouchEnd
```

通过 `XISelectEvents` 选择 `XIAllMasterDevices`，从 `XIDeviceEvent.sourceid/deviceid`
查询设备类别；主指针事件和 slave 事件不会重复上报。

### 7.2 键盘

- 调用 `XkbSetDetectableAutoRepeat(display, True, &supported)`；
- 支持时：按键重复以 `KeyPress` 重复到达，`repeat = true`；
- 不支持时：维护 repeat rate/delay 的定时器（可选，先用 XKB 支持路径）；
- `XLookupKeysym` 或 `XkbKeycodeToKeysym` 得到 keysym，复用
  `src/linux/xkb.zig` 的 `mapKey`；
- modifier 从 `XKeyEvent.state` 映射：
  `ShiftMask`、`ControlMask`、`Mod1Mask`（Alt）、`Mod4Mask`（Super）、
  `LockMask`（Caps Lock）、`Mod2Mask`（Num Lock）。

`KeyPress/KeyRelease` 需要处理 autorepeat 的 release；使用
`XkbSetDetectableAutoRepeat` 避免生成伪 release。

### 7.3 XIM / 文本输入

每个窗口创建自己的 XIM IC：

```text
XOpenIM(display, null, null, null)
XCreateIC(im, XNInputStyle, XIMPreeditNothing | XIMStatusNothing,
              XNClientWindow, xid, XNFocusWindow, xid, null)
```

- `FocusIn` → `XSetICFocus(ic)`；
- `FocusOut` → `XUnsetICFocus(ic)`；
- `KeyPress` → `Xutf8LookupString(ic, &event, buf, size, &keysym, &status)`；
- `status == XLookupChars/XLookupBoth` 时把 UTF-8 文本推入 `text_input`；
- `XBufferOverflow` 时按返回长度重新分配；
- 没有 XIM 时回退 `XLookupString` + keysym → UTF-8；
- 文本进入 `Event.TextInput` 前必须是 UTF-8，契约与 Wayland 一致。

Preedit 暂不进入公开事件，和 Wayland 当前行为一致；后续可扩展。

### 7.4 鼠标 / 触控板

XInput2 路径：

- `XI_Motion` → `mouse_moved`；
- `XI_ButtonPress/Release` → `mouse_button_down/up`，按钮号使用 Linux `BTN_*`；
- `XIScrollClass` 对角线 valuator → `mouse_scrolled`；
- `XI_Enter/Leave` → `mouse_entered/mouse_left`，保存 `event_x/event_y`；
- 触控板点击和滚动由 compositor/驱动作为 XI2 按钮/valuator 上报；
- 没有 XI2 时使用 core `MotionNotify` / `ButtonPress` / `ButtonRelease`，
  滚轮使用 `Button4/5/6/7`。

`input_codes.zig` 或公共常量模块定义 `BTN_LEFT` 等，避免裸 `0x110`。

### 7.5 触摸屏

XInput2 `XI_TouchBegin/Update/End`：

- 只跟踪第一个 active touch id；
- `TouchBegin`：
  - `mouse_entered`（首次进入窗口）；
  - `mouse_moved`；
  - `mouse_button_down(left)`；
- `TouchUpdate`：`mouse_moved`；
- `TouchEnd`：`mouse_button_up(left)` + `mouse_left`；
- `TouchCancel`（如有）：同 up；
- 不产生 touch 类型事件，行为与 Wayland 后端一致；
- 坐标从 `XITouchEvent` 的 `event_x/event_y` 或 root 坐标转换。

### 7.6 数位笔 / 数位板

XInput2 的 slave pointer 设备包含数位笔，需要通过设备信息区分普通鼠标：

- 启动时和 `XI_HierarchyChanged` 时调用 `XIQueryDevice`；
- 缓存每个 deviceid 的：
  - 设备名（用于 eraser 判断，如名称包含 `eraser`）；
  - `XIValuatorClassInfo` 的 label/atom、min/max；
  - `XIScrollClassInfo`（判断触控板/滚轮）；
- 压力：
  - 找 label 为 `Abs Pressure` 的 valuator；
  - `pressure = (value - min) / (max - min)`，限制到 0..1；
- tilt：
  - `Abs Tilt X`/`Abs Tilt Y`，转成度；
- rotation：
  - `Abs Rotation`，转成度；
- 位置：`XIDeviceEvent.event_x/event_y`（窗口坐标）；
- 进入/离开：
  - `XI_Enter/XI_Leave`（slave pointer）→ `pen_entered/pen_left`；
- 按下/抬起：
  - `XI_ButtonPress/Release` 且设备为笔 → `pen_down/pen_up`；
- 笔按钮：
  - Linux `BTN_STYLUS`/`BTN_STYLUS2` → `pen_button_down/up`；
- 移动：
  - `XI_Motion` → `pen_moved`，带当前 pressure/tilt/rotation；
- `pen_id` 使用 XI2 `deviceid`。

如果无法可靠判断设备类型，优先按设备名和 valuator 能力判断；无法判断的 slave
pointer 仍可作为鼠标处理，不影响普通鼠标/触控板。

## 8. 剪贴板

X11 的剪贴板是 selection 机制，必须有 owner window 和事件循环配合。

### 8.1 通用 MIME API

后端实现与 Wayland 相同的通用接口：

- `getClipboardMimeTypes`
- `getClipboardData(mime)`
- `setClipboardData(mime, data)`
- `setClipboardItems(items)`
- `getClipboardText/setClipboardText` 只是文本便捷层

X11 的 selection target atom 可以直接使用 MIME 字符串（例如 `image/png`、
`text/uri-list`），内部：

```text
MIME 字符串 -> XInternAtom(target)
```

`getClipboardMimeTypes` 通过 `TARGETS` target 获取 atom 列表并转成字符串；
`getClipboardData` 使用对应 atom 做 `XConvertSelection`。

### 8.2 报错规则（与 backend.md 一致）

- 未初始化/无 clipboard owner：`error.Uninitialized`；
- 剪贴板为空或没有该 MIME 的表示：`null`；
- 异步结果未到达：`error.WouldBlock`；
- 请求的 MIME 不在 `TARGETS` 中：`error.Unsupported`；
- 返回的字符串/数组由调用方释放；
- `setClipboardData` / `setClipboardItems` 必须复制 MIME 和字节。

### 8.3 发送方向

- 创建不可见 `clipboard_window`，`XSelectInput(PropertyChangeMask)`；
- `setClipboardItems` 保存多个 MIME + 字节 item，并 `XSetSelectionOwner(CLIPBOARD)`；
- 收到 `SelectionRequest`：
  - `TARGETS` → 返回所有 MIME atom + `TARGETS`；
  - 请求的 target 对应某个 item → `XChangeProperty(..., target, 8, data)`；
  - 未知 target → 拒绝；
  - 发送 `SelectionNotify`；
- 多个 item 可以同时提供 `text/plain`、`text/html`、`image/png`、`text/uri-list`；
- 大对象使用 `INCR`；第一版可对超过阈值的数据返回拒绝或简化处理。

### 8.4 接收方向

- `getClipboardMimeTypes` 请求 `TARGETS` 并缓存 atom → MIME；
- `getClipboardData(mime)` 请求对应 target，收到 `SelectionNotify` 后读取 property；
- `PropertyNotify` 用于大对象/异步结果；
- 在数据到达前返回 `error.WouldBlock`，不阻塞事件循环；
- selection owner 取消或窗口销毁时清理缓存；
- 文件列表是 `text/uri-list` 的字节，不做文件系统操作；
- 图片是编码后的 `image/png` 等字节，不转换为 RGBA；
- `STRING` / `UTF8_STRING` 作为文本兼容 target；统一 UTF-8 输出。

### 8.5 XDND 文件拖拽

X11 文件拖拽使用 XDND（不是 CLIPBOARD），第一版实现接收和发送的最小集合：

- 目标窗口设置 `XdndAware` property，版本 5；
- 接收 `ClientMessage`：
  - `XdndEnter`：读取 `XdndTypelist`，优先 `text/uri-list`；
  - `XdndPosition`：回复 `XdndStatus`，声明接受 copy；
  - `XdndLeave`：清理状态；
  - `XdndDrop`：通过 `XdndSelection` 转换 `text/uri-list`，完成后发送
    `XdndFinished`；
- 发送拖拽：
  - 设置 `XdndSelection` owner；
  - 处理 `SelectionRequest` 返回 `text/uri-list`；
  - 处理目标窗口的 `XdndPosition`/`XdndStatus`/`XdndFinished`；
- 数据仍然是 URI 列表，不打开文件；
- `Window.startDragFiles` 的语义与 Wayland 一致；
- 大 URI 列表可用 INCR，第一版限制大小。

## 9. 监视器 / 光标 / 工作区

### 9.1 监视器

优先 XRandR：

- `XRRGetMonitors(root, true)` 获取逻辑 monitor；
- 每个 monitor：
  - `name` atom → 字符串；
  - `x/y/width/height`；
  - 主输出；
  - `XRRGetOutputInfo` / `XRRGetCrtcInfo` 获取 refresh rate；
- `RRScreenChangeNotify` 或 `RRNotify` 触发重建；
- 没有 XRandR 时创建一个基于 `DisplayWidth/DisplayHeight` 的兜底 monitor；
- `work_area` 从 EWMH `_NET_WORKAREA` 读取，按 monitor 位置近似切分；
- `dpi_scale`：读取 root 上的 `Xft.dpi` 资源，`scale = dpi / 96.0`，默认 1.0。

### 9.2 光标

- 使用 core Xlib `XCreateFontCursor`，不依赖 libXcursor；
- `General.Cursor` → `XC_*`：
  - `arrow` → `XC_left_ptr`
  - `ibeam` → `XC_xterm`
  - `crosshair` → `XC_crosshair`
  - `pointing_hand` → `XC_hand2`
  - 各 resize → `XC_sb_*` 或 `XC_bottom_*`
  - `not_allowed` → `XC_X_cursor`
  - `wait` → `XC_watch`
- 设置：`XDefineCursor(window, cursor)`；
- 自定义图案：`Window.setCursorImage(state, image)` 按 `General.Cursor` 状态配置
  调用方 RGBA；`clearCursorImage(state)` 恢复系统 shape；
- 库不内置 move/文件图案；
- 隐藏：`XCreatePixmapCursor` 1x1 全透明，或 `XDefineCursor` 到 blank cursor；
- 销毁：窗口销毁时释放 cursor；共享 cursor 由 Backend 缓存。

## 10. 构建集成

目标命令（X11 后端实现后才可执行；当前会被构建期拒绝）：

```bash
zig build test -Dbackend=x11
zig build test          # 顶层 backend 选择 x11 后
zig build run example -Dbackend=x11
```

`build.zig`：

- backend selector 生成 `src/backend_selected.zig`：
  ```zig
  pub const impl = @import("linux/x11/backend.zig");
  ```
- 只有 `backend == .x11` 时：
  - 生成 `src/linux/x11/bindings.zig`；
  - 不生成 Wayland 协议文件；
  - 不链接 X11/Xi/Xrandr，只 `link_libc`；
- `addApiTest(..., .x11, ...)` 增加 `x11` 步骤；
- `example` 的模块复用同一个 `zcwl` 模块，因此也会自动使用 X11 后端。

公共代码复用：

| 现有代码 | X11 用法 |
|---|---|
| `src/linux/egl.zig` | 增加 `PLATFORM_X11_KHR`，其余复用 |

## 11. 风险与实现顺序

### 11.1 已知风险

- Xlib 的 `XEvent` ABI 依赖头文件；必须用 translate-c 生成，不手写 union。
- 不链接 X11 时，dlopen 失败必须降级/报错；`XEvent` 类型不代表函数可用。
- XIM 输入法在部分环境不可用，必须回退 keysym 文本；编码统一 UTF-8。
- XInput2 数位笔设备类型没有统一的“tool type”字段，erasure 只能用设备名/
  valuator 能力判断；不同驱动命名可能不同。
- 同时选择 core 和 XI2 指针事件可能重复，必须只保留一条路径。
- 置顶、全屏、装饰、透明度都依赖 WM/EWMH/compositor，不保证所有 WM 生效。
- X11 没有统一的 fractional scale；`Xft.dpi` 是近似值。
- 剪贴板异步、可能被 owner 取消；大文本 INCR 第一版可不支持。
- 没有 compositor 时逐像素透明和整窗 opacity 都不会生效。

### 11.2 建议实现顺序

1. `loader.zig` + `bindings.h` + translate-c 生成；
2. `display.zig` + `backend.zig` + 事件泵；
3. `window.zig` + EWMH 基本窗口操作；
4. `keyboard.zig` + `input.zig`（core 键鼠 + XIM）；
5. `egl.zig` 的 X11 platform + `context.zig`，先让 example 出三角形；
6. `pointer.zig` XInput2 鼠标/触控板/触摸映射；
7. `tablet.zig` XInput2 数位笔压感/tilt/rotation/按钮；
8. `monitor.zig` + `cursor.zig`；
9. `clipboard.zig` + `ewmh.zig` + `ime.zig` 完整化；
10. `vulkan.zig`；
11. `zig build x11` API 测试 + `example` X11 运行验证；
12. 性能/兼容性收尾：XI2 热插拔、INCR、WM 差异、无 compositor 路径。
